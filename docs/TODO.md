- [ ] `01M3YMBZP` trk show returns a compacted task's final body: compact stores it in the tombstone record; tombstones --rebuild backfills pre-index ids once from history; compacted tasks stay read-only #tombstones #compact

  <details><summary>Scott, 2026-10-02 (Enix session, "ok, that sounds good to me"): keep a…</summary>

  Scott, 2026-10-02 (Enix session, "ok, that sounds good to me"): keep a compacted task's final body readable.

  PROBLEM: trk compact removes a task from the live store and records only a tombstone (id, short, title, prior state, arcs, collected time). `trk show <compacted id>` therefore answers COMPACTED with a title and no body. Enix carries roughly 18,585 historical citations (measured by its dangling-tracker-id-lint, 2026-09-12) to ids whose content is now unreadable through trk. A comment-migration pilot found most ids its code comments cited were compacted. One surviving title (01M1M0HR4) describes a different fix than the code cites it for, so a reader following it is misled.

  SHAPE (ruled by Scott in that exchange):
  1. At compaction time, compact writes each task's FINAL body (the fold of the snapshot plus setBody/appendBody events) into that task's tombstone record. This is one write into a file trk already owns. No git access on the read path.
  2. `trk show <compacted id>` prints the stored body under the existing COMPACTED header. The exit code stays 2 (compacted).
  3. BACKFILL, once: `trk tombstones --rebuild` already replays the tracker log's git history to recover ids compacted before the index existed. Extend that same pass to recover each such id's last body into its tombstone. After the backfill, nothing consults git.
  4. READ-ONLY. A compacted task stays non-appendable: no edit/append to a compacted id. A compacted task is not a destination for new prose.

  Cost: the tombstone file grows by the bodies of compacted tasks. It is read only when `show` misses the live store, so compaction's purpose (a small live store and snapshot that every command loads) is unchanged.

  Rule 5: a test where compacting a task with a body and then running `show` returns that exact body (including an appendBody delta written after the last setBody); a negative arm where an edit/append to a compacted id is refused; and a rebuild test where a pre-index compacted id's body is recovered from replayed history.

  </details>
